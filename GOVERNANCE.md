# Governance

Work is maintained in the open by repository maintainers.

- Changes land through reviewed pull requests with required CI.
- User-visible releases use Changesets and protected staged publication.
- Maintainers own security response, compatibility decisions, and release
  approval.
- Significant scope changes require a public proposal before implementation.
- The narrow product boundary is part of governance: Work coordinates and
  validates work but does not become an agent harness or Git/CI system.

At least two GitHub and npm owners are recommended before 1.0. Maintainers may
add contributors based on sustained, trustworthy participation. Inactive access
may be removed to reduce supply-chain risk.
